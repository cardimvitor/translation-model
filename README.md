# Translating city and product names into English with small models

An experiment: how far can small models that run offline, on a phone or one CPU thread, go at translating short names into English? The names are cities, countries, regions, street addresses and product names, written in 16 languages: zh es pt ar ru ja ko de fr hi tr id vi it pl th. Each input can also be romanized instead of translated (transliteration).

Between Nov 4 and Nov 16, 2026, 25 versions were built and measured on the same tests, from a rules-only first version to a 0.050B-parameter neural model. Everything was trained on a 4-core CPU with no GPU. The best version is compared below with Tencent's Hy-MT2 (1.8B and 7B parameters), OPUS-MT and NLLB-200.

The full report, with every version, every test and every experiment that failed, is [reports/pdf/label-normalizer-report.pdf](reports/pdf/label-normalizer-report.pdf). Its web version is generated by `build/make_report_v2.py`.

The tests were never used for training:
- **Short names:** 320 product names written by hand for this project (20 products in 16 languages).
- **English + Turkish mixed:** 64 hand-written names that mix English and Turkish words.
- **Product names:** 330 real product names written by people, held out before training. The same 330 were used for every model because Hy-MT2-7B needs about 6 seconds per name.
- **Places tests:** 160 and 101 hand-written cities, towns, regions, addresses and names to romanize.

**Exact** means the output equals an accepted English answer. **chrF** is a character-overlap score from 0 to 100. Our models run with their rules; the others run alone. The report has the table for all 25 versions.

**What the numbers show:**
- v14 is better than every existing model in the table on real product names, and better than all of them except Hy-MT2-7B on short names.
- Hy-MT2-7B stays ahead on short names (by 7.4 chrF) and on mixed-language names. It is 140 times larger and about 200 times slower.
- On the two thirds of names v14 marks as *reliable*, the two are level in chrF (95.9 against 95.3).

## How it works

A name goes through four steps:

1. **English check.** A 100 KB character model says whether the text is already English. A word-level check against 26,000 English words catches a single foreign word inside an English name.
2. **Places and addresses.** A place list built from GeoNames and Unicode CLDR gives the English name of 2.1 million names of countries, regions, cities, towns, villages, islands and districts. Address rules translate the street-type word and romanize the street name, for example "ул. Ленина 5" becomes "Lenina Street 5". There is no list of streets.
3. **Known words.** A word list of about 1,800 product terms per language handles names in which every word is known.
4. **Neural model.** Everything else goes to a small translation model with one 1.6 MB expert per language. Its answer is used only when it is confident enough; otherwise the romanized form is kept.

Every answer is marked *reliable* or *needs review*. Transliteration has its own rules for each writing system, word readings for Arabic and Hindi mined from place names, and tables of common Korean, Chinese and Japanese surnames.

The same logic is written twice, in Python and JavaScript, and the two give identical answers on all 3,018 rule checks.

## What the experiment found

- **The starting point mattered most.** Twelve models trained from nothing (v3 to v5) moved short-name chrF from 43 to 51. One fine-tune of a pretrained translator, OPUS-MT mul-en, moved it to 80.
- **Data that looks like the task beats more data.** Real product names and short search phrases helped more than doubling the translated titles.
- **Much of the remaining error was in the training data.** Hy-MT2-7B was used as a judge: in about seven of ten names the model got "wrong", the training answer itself was wrong. Removing and correcting those pairs became v11.
- **Measure the model alone before retraining.** For mixed-language names, more training made things worse; a rule that never let those names reach the model was the real cause.
- **A smaller model can be better and faster** when the cut follows a measurement. v8 kept 2 of the 6 decoder layers and an English-only output layer, and it was half the size, twice as fast and more accurate.
- **Some ideas did not pay off:**
  - A JEPA pretraining experiment worked technically but lost to ordinary training given the same hours.
  - Two training runs were rejected by the automatic pass/fail gate.
  - Blends of old and new weights never beat the originals.

## Models in this repository

| Folder | What it is |
|---|---|
| `models/student_V14` | **v14, the main model.** 0.050B parameters, 57 MB at 8-bit, plus a 1.6 MB expert per language. |
| `models/student_V14F2` | **v14 Fast v2.** Cut from v14's weights (3 encoder layers, 1 decoder layer) and retrained for 3 hours. 0.035B parameters, 42 MB. |
| `models/student_V14F1` | v14 Fast v1: v8 Fast's weights with the v14 rules. |
| `models/student_V6` … `student_V13`, `student_V8F` | Earlier pretrained versions; the report says what each one changed. |
| `models/student_v3`, `student_A`, `student_B`, `student_C`, `student_B2`, `student_C2`, `student_H`, `student_ALL3`, `student_HY`, `student_MAX`, `student_JEPA`, `student_BASE` | The earlier models trained from nothing, and the JEPA experiment. |

`weights/` holds full-precision copies of v6 and every later version, split into parts. `training_data/` holds every training pair and teacher translation (gzip). `reports/` holds each version's results, logs and the report. The neural files are ONNX, run with onnxruntime (Python) or onnxruntime-web (JavaScript).

## Try it

```sh
pip install -e ".[accurate]"
echo '[["translate","Москва"],["translate","кожаная сумка женская"],["transliterate","東京"]]' > in.json
NEURAL_DIR=student_V14 en-normalize in.json --model accurate
```

```js
const kit = ENNormalizerKit.createNormalizer({ baseUrl: "/", model: "accurate", variant: "student_V14", ort: window.ort });
const out = await kit.normalize([["translate", "Wien"], ["translate", "black deri ceket"], ["transliterate", "김민준"]]);
```

Each result has the output, the method used, a confidence, the detected language and the reliable mark. `web/index.html` is a test page that runs v14 and v14 Fast v2 in the browser; build it with `sh build/stage_web.sh` and serve `web/dist/`.

## Training it further

Three ways, each with an automatic pass/fail check against the previous model:
- add words directly with `build/add_terms.py`;
- train on new pairs with `sh build/post_train.sh student_V14 student_V15 120 my_pairs.jsonl`;
- turn an English-only list into pairs with `build/make_pairs.py`.

Step by step in [docs/ADDING.md](docs/ADDING.md). `build/` holds every script used to make each version; the report lists which one made what.

## Limits

- Not error-free: about one answer in four on short names differs from the accepted answer. Many of those are near-synonyms.
- Behind Hy-MT2-7B on short names and mixed-language names.
- No list of streets: street names are romanized, not translated.
- The place list is 77 MB and needs about 875 MB of memory in Python when every writing system is loaded; the browser loads only the writing systems it meets.
- The test sets are small, so differences under about 1 chrF between neighbouring versions are within noise.
